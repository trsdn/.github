# Profile statistics

The profile statistics generator renders GitHub account cards as static SVG
files. It is self-hosted: GitHub Actions collects data through the GitHub API,
renders SVG strings locally, and commits the output back to the repository. It
does not call `github-readme-stats`, Shields, Vercel, Leapcell, headless
browsers, external fonts, or remote images.

## Architecture

The Python package lives in `scripts/profile_stats/` and runs on Python 3.12 or
newer.

| Module | Responsibility |
|---|---|
| `github_api.py` | GraphQL and REST client, pagination, timeouts, and retry/backoff for rate limits |
| `collect.py` | Repository and account aggregation |
| `models.py` | Dataclasses for collected data |
| `momentum.py` | Completed UTC contribution periods, coverage, active days, and weekly buckets |
| `render/` | SVG rendering, themes, primitives, escaping, and formatting |
| `languages.py` | Embedded GitHub language colors; no runtime network fetch |
| `config.py` | Restricted YAML configuration defaults and validation using the standard library |
| `cli.py` | `argparse` CLI for `repo` and `account` commands |

The default account workflow is `.github/workflows/profile-stats.yml`. It runs
every six hours, on manual dispatch, and after changes to the generator on
`main`. It renders into `assets/profile-stats` and publishes the result to the
`stats` branch, and only when a generated SVG actually changed.

The rendered cards are not tracked on `main`. Committing generated output to a
reviewed branch means it drifts from the generator that produced it, and stale
files survive forever once a card is dropped from `cards.account`. `main` holds
the generator; the `stats` branch holds its output.

## Cards

Account mode renders light and dark variants for:

- `overview-card.svg`: total commits, stars, merged PRs, authored issues, code
  reviews, followers, active repositories, streaks, and the repository count.
  That count reads `sources / all`, for example `68 / 79`. Repository-derived
  totals ignore forks, but GitHub's profile page counts them. Contribution-based
  metrics follow GitHub's contribution rules instead. Printing only the source count
  therefore contradicts the number GitHub shows and reads as a bug; printing
  both makes the difference self-explanatory. The second figure is dropped when
  the account owns no forks.
- `activity-card.svg`: last twelve months of contributions, current streak, and
  longest streak.
- `language-card.svg`: weighted language distribution by bytes across non-fork
  repositories.
- `momentum-card.svg`: public contributions in the last 30 completed UTC days
  versus the previous 30, active days, and a weekly contribution sparkline.

`repos-table-card.svg` remains available for compatibility but is no longer
generated by default. It lists recently active repositories with stars, commits,
last commit, release, issues, and primary language. `now-building-card.svg`
renders the three most recently changed repositories with their latest commit
messages. Add `repos-table` or `now-building` to `cards.account` to opt in.

Cards size themselves from their content and are not animated. Animating a card
in from zero opacity or zero width looks empty in every renderer that snapshots
the first frame instead of playing the animation, which covers thumbnails,
previews and image converters.

Dark mode is selected in Markdown with `<picture>` and a dark `<source>`. GitHub
serves SVGs through Camo; CSS `prefers-color-scheme` media queries inside an SVG
are not reliable there, so each theme is rendered as a separate SVG file.

### Momentum semantics

The generation timestamp fixes both periods. Today is excluded because it is
unfinished: for a run on 2026-09-07 UTC, the recent period is 2026-08-08 through
2026-09-06, and the previous period is 2026-07-09 through 2026-08-07. Both are
inclusive, consecutive 30-day periods. Their exact dates and integer totals are
printed on the card. An active day has at least one public contribution in the
recent period, regardless of how many contributions it has.

The change is recent minus previous; the percentage uses the previous total as
its denominator. If that total is zero, the card prints the absolute change and
states that the percentage is undefined, including when both totals are zero.

The sparkline covers the same 60 days, from oldest to newest. Points are
Monday-Sunday contribution totals, not averages or cumulative counts. Boundary
weeks are clipped to the displayed range, marked `*`, and not extrapolated.
Labels give each bucket's starting month and day; SVG titles provide its exact
inclusive dates, total, and number of days. A partial boundary week with every
expected date present is valid; it is not missing data.

Momentum counts GitHub contribution records for commits, opened issues, opened
pull requests, PR reviews, and created repositories, only when the attributed
repository has `PUBLIC` visibility. GitHub returns the latest review contribution
for each reviewed PR, not every review event. These are contributions, not all
commits in owned repositories, and include contributions to other people's
repositories according to GitHub's contribution rules. Repository include/exclude
filters and `top_n` do not filter Momentum.

The raw `contributionCalendar` may include private contributions visible to the
token or anonymized private counts. Momentum reuses its dates for coverage, but
never its counts: `public_contribution_days` is built separately from
repository-attributed GraphQL records. Private, internal, and restricted records
are excluded even when `include_private` is enabled. The existing activity
calendar and streaks still use GitHub's calendar and may include private counts;
they are not Momentum's public-only series.

A period with a missing date is shown as unavailable, not as a smaller total.
The card reports the observed date coverage; comparison needs both periods and
the active-day count needs the full recent period. Incomplete weeks are `N/A`,
with no line across the gap. Empty or unavailable data does not become a
zero-activity claim. Issue, PR, review, and repository-creation connections are
paginated. Commit collection is bounded to 100 repositories and 100 daily
records per repository; if the API reports omitted repositories or further
daily records, collection logs a warning and Momentum is unavailable. API errors
fail the run instead of publishing fabricated zeros.

## Configuration

Edit `scripts/profile_stats/config.yml`:

```yaml
username: trsdn
top_n: 12
include_private: false
repo:
  include: []
  exclude: []
cards:
  account:
    - overview
    - activity
    - language
    - momentum
```

`cards.account` is the list of cards to generate. Valid names are `overview`,
`activity`, `language`, `momentum`, `repos-table` and `now-building`. Unknown
names, duplicate names, and non-list selections fail configuration validation
before data collection. Momentum's additional public-contribution queries run
only when that card is selected.

`include_private: true` requires a token that can read the private repositories
being counted. The workflow reads `secrets.STATS_TOKEN` when present and falls
back to `GITHUB_TOKEN`.

## Local usage

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
export STATS_TOKEN="$(gh auth token)"
PYTHONPATH=scripts python -m profile_stats account --username trsdn --out assets/profile-stats
```

`requests` is the only runtime dependency installed by `requirements.txt`. The
renderer validates every SVG with `xml.etree.ElementTree` before writing it.
Dynamic strings are XML-escaped, control characters are stripped, and SVG output
does not use `<script>`, `<foreignObject>`, external fonts, or external images.

## Profile README

GitHub renders the account profile from a repository named after the account, so
the page lives in [`trsdn/trsdn`](https://github.com/trsdn/trsdn) and not here.
A `profile/README.md` in a `.github` repository only works for organization
accounts; GitHub advertises it on personal `.github` repositories too, where it
has no effect.

This was confirmed by experiment rather than assumed. A `profile/README.md` was
committed here alongside the existing `trsdn/trsdn/README.md`, differing in a
single word so the two sources could be told apart in the rendered HTML. The
profile kept serving `trsdn/trsdn` for the whole observation window, so the file
was removed again. Do not re-add it.

That page embeds the account cards from raw URLs pinned to the `stats` branch of
this repository rather than from `main`. The reason is branch protection: `main`
rejects pushes from `GITHUB_TOKEN`, so a workflow that committed generated cards
to `main` would fail with `GH006`. Publishing to a separate generated branch
keeps the protection rule intact and keeps generated output out of the reviewed
history.

When migrating the profile to the default Momentum card, replace the existing
repository-table `<picture>` in `trsdn/trsdn/README.md` with:

```html
<picture>
  <source media="(prefers-color-scheme: dark)" srcset="https://raw.githubusercontent.com/trsdn/.github/stats/assets/profile-stats/momentum-card-dark.svg">
  <img alt="Momentum: public contributions over consecutive 30-day periods, weekly trend, and active days" src="https://raw.githubusercontent.com/trsdn/.github/stats/assets/profile-stats/momentum-card.svg">
</picture>
```

Do this after the updated generator has published both Momentum variants to
`stats`. That README edit is a separate integration step in `trsdn/trsdn`; a
generator change here does not update the live profile. The default workflow
clears prior card output, so consumers that retain repository-table embeds must
explicitly keep `repos-table` in the configuration when switching defaults.

The `stats` branch is force-pushed on every run and holds no reviewed content.
Never base work on it.
